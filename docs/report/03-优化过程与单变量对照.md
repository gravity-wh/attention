# 3. 优化过程与单变量对照（varB bank 早释放）

> 本节是报告正文源，不是结果表附录。数据源：main `a0e713a` 的 `hw/results/tables-sm40.md`；改前行取自 `8dad36a^` 的 `varB-sm40-tt/ss/ff`。
> **注意**：`hw/results/tables-sm40.md` 里由 `make_table.py` 自动生成的“表 3”只是 Table 2 的镜像，**不是单变量对照**，不能直接贴进报告。最终报告必须用本节 3.4 的“调整前/调整后”表。
> 结论：**这是一次合法的单变量优化**——只改 `erow` bank 的释放时机；输入向量、数值模型、数值 core、数值格式、lane 数、行融合结构、seed、PDK、约束均不变。testbench 仅增加装载周期测量与汇总，不改变 DUT 激励内容。

## 3.1 优化目标

`varB` 的行流水设计目标是 80 拍/行，但 v12 实测 1,738 拍（108.6 拍/行）。目标不是“再快一点”，而是**先解释这 108.6 从哪来，再只改一个变量把它消掉**。

## 3.2 瓶颈定位：先测量，不改 RTL

用控制级逐拍模型（`hw/flow/collect/cycle_model.py`，与 RTL diff 全 0）分解 1,738：

| 项 | 拍数 | 说明 |
|---|---:|---|
| 前导 | 82 | 首行 A 启动到首行 C 开始 |
| A 级 | 8 × 81 | 奇数行 |
| bank 等待 | 8 × 45 = **360** | 偶数行多等 45 拍 |
| 行间隔 | 81 / 126 交替 | 两个 bank 同时被占住 |
| 总计 | **1,738** | 82 + 8×81 + 8×126 |

单 bank 占用 = `1 + 81 + 45 + 80 = 206` 拍；两个 bank 的吞吐上限 ≈ 101.5–109.5 拍/行，实测 108.6，对得上。

**这一步的判据**：如果 bank 等待不是主项，就不许动 RTL，回到 A 级或 B 级找原因。

## 3.3 改动：只挪两行

`erow[c_bank]` 的唯一读者是 C 级归一化的 `pr_mul = erow[c_bank][c_j] * c_rval`；归一化 16 拍读完后，P·V 只读 `pu_row` / `nzrow_r`，不再碰 `erow`。因此 bank 可以在**归一化结束**释放，而不是等 P·V 的 64 拍走完。

```diff
- // P·V 结束后释放
- if (c_bank == 0) bank_busy[0] <= 0;
+ // 归一化已把 erow[c_bank] 整行读完
+ if (c_bank == 0) bank_busy[0] <= 0;
```

单 bank 占用从 **206 → 142 拍**（`1 + 81 + 45 + 16`），bank 等待从 360 拍降到 0。

**没有改的东西**：数值格式、exp/recip 语义、lane 数、行融合结构、`pu_row`/`nzrow_r` 的读写顺序、端口、tb。

## 3.4 单变量对照（表 3 正文）

**改变的变量**：`erow` bank 的释放时机（P·V 末 → 归一化末）。
**保持不变的条件**：工艺 SC9MC、工具 Genus 15.20 / VCS V-2023.12-SP2、角 TT_25C_1V10、100 MHz、seed 20260101、驱动/负载、数值格式 qb10/qf7、输入向量与六类激励内容、数值模型、数值 core、综合约束及 PVT 均不变；testbench 仅增加装载周期测量与汇总，不改变 DUT 激励内容。

| 项目 | 调整前（`8dad36a^`） | 调整后（`a0e713a`） | 变化 |
|---|---:|---:|---:|
| 变量取值 | bank 在 P·V 末释放 | bank 在归一化末释放 | — |
| 纯计算周期 | 1,738 | **1,423** | −18.1% |
| 端到端周期（含 768 装载） | 2,506 | **2,191** | −12.6% |
| 最大单帧 RMSE | 0.002492 | 0.002492 | 不变 |

| 运行频率 | 100 MHz | 100 MHz | 不变 |

| 功率 P（mW） | 16.024 | 16.096 | +0.45% |

> 面积/功耗变化在 ±0.9% 内，且三个角的符号不一致（tt +0.62%、ss −0.51%、ff +0.01%），属于映射噪声，不作为优化收益宣传。**收益来自调度，几乎不花资源。**

## 3.5 验证过程

1. **先预测**：bank 占用 206 → 142，行间隔从 81/126 交替变为 81，预测总周期约 1,423。
2. **再跑 full**：`make regress VARIANT=varB TAG=varB-early MODE=full`，616 例六类全 PASS，`mism 0`，`lat_min/avg/max = 1423/1423/1423`。
3. **再跑综合**：同 PDK/角/约束重跑三角，WNS 0 / 0 / +0.001，面积/功耗在噪声内。
4. **加保险**：在 `top_varB.sv` 加 `translate_off` 断言，监控 `b2c_v` 连续高 >2 拍、`b2c_v && rcp_done` 覆盖、`a2b_v` 连续高 >2 拍；616 例 0 条触发，不加拍。

## 3.6 被否掉的方案

| 方案 | 为什么不做 |
|---|---|
| 加第三个 `erow` bank | 释放点提前后 bank 等待已是 0，第三 bank 只增加面积，零收益 |
| 给 B→C 加反压 FIFO | 当前 A 81 / B 45 / C 80 时序下 `b2c_v` 每行只占 1 拍；加 FIFO 会多 1 拍（1,423→1,424）；改用断言监控 |
| 改 C 级 P·V 的 64 拍 | 不是本次变量；动了就不是单变量对照，且会改数值时序 |
| 继续调 `csz==1` 的调度 | 本轮先解决 bank；调度优化留给下一轮，不和本次改动混在一起 |

## 3.8 结论

这次优化回答的是“**为什么 1,738 不是算术慢，而是 bank 被占住**”，并用一次只改两行的实验把它变成 1,423。精度零代价，面积/功耗在噪声内，时延/能耗端到端各降约 12.6% / 12.2%。这条过程可以独立复现，也可以作为表 3 的单变量对照直接引用。
