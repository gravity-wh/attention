> 盘点对象：`H:\BaiduPan\L294 单元库与PDK`（16 个目录，174 个文件，全部为压缩包）
> 判定目标：能否在 VM（CentOS）的 **Innovus 15.20** 上跑完
> 综合 → 布局 → CTS → 布线 → 寄生提取 → STA → 输出网表/GDS 的**全流程**
> 判定时间：2026-11-02

---

## 1. 判定标准：Innovus 跑完 PnR 的七项硬输入

| # | 项 | 缺失后果 |
|---|---|---|
| ① | **tech LEF**（LAYER/VIA/SITE/DRULE） | 无布线层与设计规则，`init_design` 直接失败 |
| ② | **单元 LEF**（MACRO + SIZE + PIN + OBS） | 单元无法摆放、无引脚几何 |
| ③ | **多角时序库**（.lib NLDM 或 .db，至少 tt/ss/ff） | 无法做时序驱动布局、无法 STA |
| ④ | **GDS / Milkyway / OA** | 无法 stream out，无法 DRC/LVS |
| ⑤ | **寄生提取模型**（TLU+ / nxtgrd / qrcTechFile / capTbl） | 布线后可提取 RC，但精度不可信 |
| ⑥ | **DRC/LVS 规则**（Calibre/Assura） | 无法签核复核（不影响 PnR 本身） |
| ⑦ | 工具链格式与版本匹配 | 库读不进或读错 |

> ③ 是分水岭：只有 ①②④ 能"布通"，但做不了时序收敛；只有 ③ 没有 ①② 只能综合。

## 3. 逐条证据

### 3.1 SAED 90 nm（`oc8051项目工艺库/library_20150117.tar.gz`）

Synopsys 教育库（SAED = Synopsys Armenia Educational Department），**就是为 Innovus 教学流程设计的**。

```
library/stdcel/lef/saed90nm_tech.lef      ← 官方 tech LEF，36 个 LAYER 段
library/stdcel/lef/saed90nm{,_hvt,_lvt}.lef
library/stdcel/lib/{ss1p08vm40c, ff1p32vm40c, tt1p20v25c, ff1p32v125c, ss1p08v125c}/
library/stdcel/db/                        ← 同角 .db
library/stdcel/milkyway/saed90nm_dv/      ← CEL + FRAM
library/stdcel/gds/, cdl/, verilog/
library/mem/                              ← SRAM macro：lef/gds/mw/lib/db/verilog 全套
library/tech/icc/saed90nm_icc_1p9m.tf     ← ICC techfile
library/tech/icc/tluplus/                 ← Cmax / Cmin / nominal 三份 TLU+
library/tech/starrc/nxtgrd_mf/            ← StarRC nxtgrd
```

- 5 组 PVT 角 × 3 种阈值（typ/hvt/lvt）× 3 种形态（普通/CG/低功耗）→ 角组合远超三方案对比所需。
- 唯一短板：**没有 Calibre deck**（教育库不提供），DRC 只能用 Innovus 内建 `checkDesign` 做几何检查，不能签核。

### 3.2 XMC 55 nm RFSOI（`XMC55nm/X55RXR1.2LSTD1p2V10T_*.tar.gz`）

这是本批里**唯一自带 `innovus_tf/` 目录**的库——厂商明确为 Innovus 出过 techfile。

```
XMC55RFSOI_..._PMK_v100g2_1.0/
├── lef/XMC55RFSOI_XR12_10TC250TL_PMK.lef
├── innovus_tf/XMC55SOI_1P3M_2Ic_TM2_ALPA_innovus.tf   ← Innovus 专用
├── icc_tf/                                            ← ICC 专用
├── lib/{iso,h2l,l2h,pmk}/   344 个 .lib（nldm + ccs，tt/ff × 25/125/-40 ℃）
├── gds/、cdl/、verilog/、atpg/
├── milkyway/XMC55RFSOI_..._PMK_1P3M/   ← 三种金属栈
├── oalib/                              ← OA 库（cds.lib + LVLLHD1 等）
├── lpe/、rln/                          ← 寄生/RLN 模型
└── calibre LVS（在 20241216084446.rar 里）
```

- 344 个时序库覆盖 level-shifter（h2l/l2h）、isolation、PMK 三类特殊单元，是完整的低功耗流程库。
- 注意：RFSOI 是**绝缘体上硅**，Innovus 布线不受影响（well/STI 已在 LEF 与 MW 内定义），但 LVS 必须用 SOI 器件识别规则。

### 3.3 TSMC 90 nm（`tsmc90工艺standardcell库pdk/`，45 个 rar 分卷）

包内其实是**两套库并存**：

| 套件 | 内容 | 用途 |
|---|---|---|
| `fe_TSMCHOME_tpdn90g18_130a` | TSMC 官方 `tpdn90g18/g2/g3` 三套库 × tc/bc/lt/wc 四角 = 25 个 .lib，5/6/7/8/9lm 五栈，Milkyway `frame_only`（含 IO PAD FRAM） | 主用 |
| `aci/sc-x` | Artisan SC-X 库，**含 `tsmc090lk_*_tech.lef`（真 tech LEF）** | 补 tech |

- 缺 **TLU+ / capTbl** → 布线后 RC 提取只能用 Milkyway 的近似或自建 captbl。
- 缺 **GDS**（0 个 `.gds`）→ 不能 stream out 做 DRC。
- 两个套件的金属栈必须对齐（`tpdn90g18` 的 5lm 与 `tsmc090lk_5lm_1thick` 是同一栈），混用会报层不匹配。

### 3.4 TSMC 0.18（`TSMC180/`，zip→rar 1.17 GB）

`CM018RG` 只有三类 IP + 文档，**没有 foundry 工艺包**：

```
CM018RG/IP/STD/tcb018g3d3_280a.tar.gz   ← 标准单元库（327 MB）
CM018RG/IP/IO/tpa018nv_270a.tar.gz
CM018RG/IP/SRAM/sram_sp_hdf_rvt_rvt.tar.gz
CM018RG/Doc/*.pdf                        ← 设计规则只有 PDF
```

`tcb018g3d3` 解开后是完整单元库：`lef/{4,5,6}lm.lef`、`gds`、`milkyway/cell_frame`（6 个角 `.db`）、`timing_power_noise/CCS`（2 个 CCS lib）、`spice/lpe_spice/verilog/vital`。

- 缺 **tech LEF**：`lef/techfiles/` 里只有 Virtuoso `virtuoso_018um_{3,4,5,6}M.v28a.tf` —— 需要走本项目 `flow/pnr/gen_techlef.sh` 那条转换路。
- 缺 **TLU+**。

### 3.5 SMIC 0.18（`数字后端库-smic0.18/smic181pv0.tar.gz`）

工艺文件最"豪华"，但**单元时序库缺席**：

```
smic180/techfile/SmicVTTF_log018.tf        ← 官方 techfile（4/5/6lm）
smic180/lef_antenna/smic18_{4,5,6}lm_antenna.lef
smic180/itf_tluplus/smiclog018_{4,5,6}lm_{cell,tran}_{max,typ,min}.{nxtgrd,tluplus,itf}
smic180/calibre/{drc,lvs,rcx,antenna}/     ← 官方 Calibre 全套
smic180/digital/sc/{lef,gds2,vhdl}/        ← 单元 LEF + GDS + VHDL 行为模型
smic180/digital/pll/S018PLLGS_500/         ← 只有 PLL 有 .lib/.db
```

- `.lef` 共 13 个，全包**没有任何标准单元的 `.lib`/`.db`**（唯一的 lib/db 属于 PLL）。
- 结论：能布通（有 LEF+GDS），但**无处可读时序**，STA 无从谈起。补 .lib 需自表征（Liberate），不现实。

## 4. 与 VM / Innovus 15.20 的匹配分析

### 4.1 读库路径

Innovus 15.20 的四种入口，对应本批库的可用性：

| 入口 | 命令 | 本批谁有 |
|---|---|---|
| LEF | `init_lef_file {tech.lef cell.lef}` | SAED90、XMC55、tsmc90、TSMC180、SMIC018 |
| 时序库 | `read_lib` / `set init_mmmc_file`（NLDM 或 CCS） | SAED90、XMC55（最全）、tsmc90、TSMC180（.db） |
| Milkyway | `set init_mw_dv` / 直接作为 design library | SAED90、XMC55、tsmc90、TSMC180、SMIC018 |
| OA | OA 参考流程 | XMC55（`oalib/`） |

### 4.2 三个版本/格式陷阱

1. **Milkyway 版本代差**：Innovus 15.20 读 MW 5.x 没问题；SMIC018 的 `digital/pll/Apollo/` 是 **Apollo（MW 3.x 时代）** 格式，很可能读不进 —— 这只影响 PLL，不影响标准单元。
2. **`.db` 与加密**：TSMC/SMIC 的部分 `.db` 带 DataX/FLEXlm 加密，VM 上没有对应厂商 license 会 `read_lib` 失败。**SAED90 与 XMC55 的 `.lib` 是明文 NLDM，无此风险** —— 这是它们最适合当前 VM 的现实原因。
3. **CCS 与 NLDM 的选择**：XMC55 同时给 nldm 与 ccs；STM 流程里 Genus 用 NLDM，Innovus 用 CCS 更准。tsmc90 只有 NLDM（Artisan 时代），精度略降但可用。

### 4.3 频率与规模估算

| 库 | 同 RTL 的大致面积倍率（相对 40 nm） | 100 MHz 能否收敛 |
|---|---|---|
| SAED 90 nm | ≈ 2.6 ~ 3.2× | 轻松（90 nm 的 100 MHz 属低频） |
| XMC 55 nm | ≈ 1.5 ~ 1.8× | 轻松 |
| TSMC 90 nm | ≈ 2.6 ~ 3.2× | 轻松 |
| TSMC 0.18 | ≈ 9 ~ 12× | 轻松，但面积巨大 |

> 面积倍率按 `(L/L₀)²` 粗估再打折（实际受标准单元高度与布线资源影响）。**引用时必须标"估算"**。

## 5. 三条可执行路径

### 路径 A（推荐）：用 SAED 90 nm 做"官方 tech LEF"对照组

这是唯一能**直接回答 07 文档遗留问题**的做法：当前 38 万 DRC marker 里有多少是"生成的 tech LEF 规则不对"。

1. Genus 用 `saed90nm_typ.lib` 重综合（改 `pdk.mk` 增一个 `PDK=SAED90`）；
2. Innovus 用 `saed90nm_tech.lef` + `saed90nm.lef` + TLU+ + MW，跑同一套 PnR 脚本；
3. 对比 DRC marker 数量与类型 → 得到"规则正确时的基线"；
4. 报告写："官方 tech LEF 下 DRC = X，生成 tech LEF 下 = 380 kX，其中 Y% 源于规则失真"。

代价：面积与频率不可与 40 nm 直接比（需注明工艺不同），但**方法论对照价值最高**。

### 路径 B：用 XMC 55 nm 做"真实量产库"对照

自带 `innovus_tf` + Calibre LVS，签核链条比 SAED 更完整。代价是 SOI 工艺的 LVS 规则更复杂，且 55 nm 与 40 nm 的可比性仍需换算。

### 路径 C：保持 40 nm，补 GF 28 的 foundry PDK

只有走 NDA 渠道才可能。本批 85 个包**确定不含** foundry tech LEF/tf/TLU+，不要在这上面继续花时间。

```bash
"/c/Program Files/WinRAR/UnRAR.exe" lb <pkg>.rar

tar -xzf <pkg> -O <path>/xxx_tech.lef | grep -c '^LAYER'
```
