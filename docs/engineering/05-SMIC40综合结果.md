# SMIC 40LL 综合结果（三方案 × 三角）

> 工艺：SMIC 40LL（sc9mc base RVT c40，r1p1）· 工具：Genus 15.20
> 目标频率：100 MHz（周期 10 ns）· 数据来源：`hw/results/metrics.csv`（pdk=SC9MC）
> 生成方式：tt 用 `make pair VARIANT=<v> TAG=<v>-sm40-tt MODE=full`（回归 + 综合成对）；
> 　　　　　ss / ff 先 `make syn ... CORNER=<c>`，再用
> 　　　　　`make regress VARIANT=<v> TAG=<v>-sm40-<c> MODE=full CORNER=<c>` 补上同 TAG 的仿真半边
> 　　　　　（综合是角相关的，仿真不是；九个目录现在都有 `summary.csv` + `syn/`）
> **全部九次综合于 2026-11-12 重跑**，对应 commit `613ec89`（含 10-30 的两处 RTL 优化）。

## 0. 一句话结论

三套实现、三个工艺角共 9 次综合**全部满足 100 MHz，违例路径 0**（最差裕量 +0.005 ns，出现在 ref 的 ff 角）；
varB 在面积、功耗、单元数三个维度上以 **2.2~2.6 倍**领先，且这个优势在三个角上方向一致、幅度接近。

与优化前的旧版数据相比（见 §3.2），三套实现的面积同时下降 15%~27%，**varB 的相对优势从 2.07× 扩大到 2.35×**——
去掉整行缓冲省下的 4 096 个触发器对 varB 这种小面积实现是更大比例的收益。

## 1. 为什么换到 SMIC40

GPDK045 是预测性 PDK，它的单元面积和延迟不对应任何可制造工艺，因此：

- 它的"面积改善倍数"没有工艺意义；
- 它的慢角结论（ss 角 WNS −2.563 ns，只能跑约 80 MHz）不能当作设计结论。

SMIC 40LL 是真实商用库，`.lib` 自带真实面积（`BUFH_X4M_A9TR40` = 1.9152 µm²，与 LEF 的 1.52×1.26 完全一致），所以本页数字可用于报告与答辩。

## 2. 工艺角

## 4. 三条要写进报告的结论

**4.1 三个角都满足 100 MHz，与 GPDK045 的结论相反**

GPDK045 的 ss 角是 WNS −2.563 ns（约 80 MHz）；换到真实 40nm LL 后 ss 角 WNS = 0。原因是预测性 45nm GPDK 的单元被过度表征，比真实 40nm LL 慢。**不要沿用 GPDK045 的"慢角不收敛"结论**。

**4.2 varB 的优势是量级级别且跨角稳定**

面积 2.19–2.38×、功耗 2.31–2.59×、单元 2.03–2.16×，三个角方向一致、幅度接近。
**能耗差得更多：E₀/E = 12.87（ss）~ 14.40（ff）**，因为 varB 同时赢在功耗和周期数（1 738 vs 9 665，5.56×）上。
面积优势只有 2 倍、能耗优势有 13 倍，这个落差的来源必须讲清楚：**面积只反映"同时存在的硬件"，不反映"用了多少个周期"**。
所以"varB 省一半面积"是低估，"varB 省一个数量级的能量"才是它的实际卖点。
这说明优势来自结构（行融合避免了 S/P 全矩阵的存储与运算），而不是某个角上的优化巧合。

**4.3 varA 只小胜 1.1~1.15 倍，不要说成"接近一半"**

三个角上 varA 面积都是 ref 的 0.87~0.89，功耗 0.95~0.99，单元 0.89~0.90。**varA 与 ref 属于同一量级**，
它的价值不在面积，而在周期数（2 855 vs 9 665，3.39×）——用 14% 的面积换 3.4 倍的吞吐。
报告里若把 varA 说成"显著更省面积"会与 1.14× 这个数字冲突。

> 附录：优化前 varA 在 ss 角功耗是 41.54 mW、比 ref 的 40.35 mW **高 3%**，是个反常点
> （tt/ff 角都低约 10%）。重跑优化后设计后该项变成 34.22 vs 34.58（**低 1%**），
> 反常消失。若答辩被问到"为什么慢角反转"，正确回答是：那是旧版设计的现象，
> 已随整行缓冲的删除一起消失，不是 4 lane 结构的固有缺陷。

## 5. 口径声明（写报告必须带上）

- **面积是纯 cell 面积**：SMIC40 的 LEF 是 macro-only（无工艺层），流程用 `SYN_PHYS=0` 跳过 `read_physical`，面积取 `.lib` 的 `area` 字段，因此 `net_area_um2 = 0`。
- **不可与 GPDK045 的面积直接相减**：那边是 cell + net（如 ref tt 348,926 + 92,709 = 441,635）。跨工艺只能比趋势，不能比绝对值。
- **时序是综合后 STA**：ideal clock + 无布线寄生；真实时序要等 P&R + qrc 提取。
- **功耗是固定活动率假设的静态估计**（toggle 0.1 / static 0.5），不是仿真功耗。
- 采样率：**100 MHz 是目标值**，`fmax_mhz` 在 WNS=0 时回填为 100，不代表器件上限。
- **周期数 = `start` 到 `done`**，即纯计算拍数，**不含装载**。`tb_attn.sv` 的 `drive_load()`
  在拉 `start` 之前先把 Q/K/V 共 768 个元素逐拍写入（3 × 256，`ld_en` 一拍一个），这 768 拍
  不在 `cycles` 里。若按"从开始装载计时"的口径，三方案各 +768：
  **ref 10,433 / varA 3,623 / varB 2,506 拍**，D₀/D 由 5.56× 降为 4.16×、E₀/E 由 14.07 降为 10.5×。
  两种口径都成立，但**必须全表统一**；本仓库一律用"纯计算拍数"，报 D/E 时说明这一点。

## 6. 复现

```bash
# tt 角：一次命令同时产出仿真与综合，两者落在同一 runs/<TAG>/ 下（表 2 的 D/E 靠这个）
make pair VARIANT=ref TAG=ref-sm40-tt MODE=full

# ss / ff：先综合（角相关），再补同 TAG 的仿真半边（角无关，但成对才能算 D/E）
for c in ss ff; do
  for v in ref varA varB; do
    make syn     VARIANT=$v TAG=$v-sm40-$c CORNER=$c
    make regress VARIANT=$v TAG=$v-sm40-$c CORNER=$c MODE=full
  done
done

make collect     # 扫 runs/ → results/metrics.csv（末尾会打印每个方案的配对状态）
make table                              # → results/tables.md（含两个工艺的全部行）
make table TABLE_PDK=SC9MC TABLE_OUT=results/tables-sm40.md    # → 只有 SMIC40 九行
```

实测耗时（16 GB VM，`SYN_CPUS=8`）：full 回归 616 例 ≈ 3 分钟（编译占其中 1 分钟），
单角综合 tt≈4 分钟、ss≈9 分钟、ff≈7 分钟；整轮九次综合 ≈ 50 分钟。
补 ss/ff 六个角的仿真半边（12:21:03 → 12:33:03，共 **12 分钟**）——因为综合已经在了，不需要重跑。
**不要为补 D/E 去重跑 `make pair`**：它会连综合一起再做一遍（多花 40 分钟），而单角综合是确定性的，重跑不会改任何一个数字。

关键参数：`SYN_PHYS=0`（SMIC 面积来自 .lib）、驱动单元 `BUFH_X4M_A9TR40`、负载 0.016 pF、时钟不确定度 5%、I/O 延迟 25%。

### 6.1 两个会把你卡住的坑（本次重跑实测踩到）

1. **VCS 会挂在外部回连上**：编译时 `vcs1` 会向 `198.182.50.26:80` 建连，
   校园网/代理环境下连上但收不到响应，进程停在 `futex_wait`，表现为"编译 12 分钟只用了 2 秒 CPU"。
   `ref` 那次侥幸没卡，`varA` 卡死。处置：`ip route add blackhole 198.182.50.26/32`，之后连接立即失败，编译正常。
2. **向量必须按数值格式逐份检查**：`_exp_qb16qf13.hex`（ref）与 `_exp_qb10qf7.hex`（varA/varB）是两套文件。
   旧 `regress.sh` 只看 `tb/vectors/s<seed>_full/` 目录在不在，于是先跑的 ref 建好目录后，
   varA 六类激励全部以"向量打不开"FAIL。已改成检查 `geninfo_<cfg>.txt` 是否存在，并把编译挪到检查之后。
