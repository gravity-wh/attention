# P2 汇报页：varB 行流水与 bank 早释放

> 一页版，答辩直接照着讲。数据源：main `be2ba27` 的 `hw/results/tables-sm40.md` 与 `docs/engineering/12-P2-工作包.md`。
> 断言补丁：`feat/p2-b2c-assert` `f968581`。

---

## 一句话

`varB` 原来 1,738 拍不是算术慢，是 **erow 两个 bank 被占太久**；把释放点从 P·V 结束提前到归一化结束，纯计算降到 **1,423 拍**，端到端（含 768 拍装载）**2,191 拍**，数值逐位不变。

---

## 1. 三级流水长什么样

```text
A 级：QK 64 + exp 16            = 81 拍/行（含取 bank 1 拍）
B 级：拉 start 1 + 长除 41 + RNE 1 + 交回 1 = 45 拍/行
C 级：归一 16 + P·V 4 组 × 16   = 80 拍/行（不存在 96；跳零组只会更少）
```

A 算第 r 行时，B 做第 r−1 行，C 做第 r−2 行。级间只有 `a2b_v` / `b2c_v` 两根握手线，行数据留在各自级本地。

---

## 2. 原来的 1,738 拍：bank 等待是主项

控制级逐拍模型（`hw/flow/collect/cycle_model.py`，与 RTL diff 全 0）：

| 项 | 拍数 | 说明 |
|---|---:|---|
| 前导 | 82 | 首行 A 启动到首行 C 开始 |
| A 级 | 8 × 81 | 奇数行 |
| bank 等待 | 8 × 45 = **360** | 偶数行多等 45 拍 |
| 行间隔 | 81 / 126 交替 | 两个 bank 都被占住 |
| **总计** | **1,738** | 82 + 8×81 + 8×126 |

单 bank 占用：`1 + 81 + 45 + 80 = 206 拍`。两个 bank 的吞吐上限约 **101.5–109.5 拍/行**，实测 **108.6 拍/行**，对得上。

---

## 3. 改动：只挪两行

```diff
- // P·V 结束后释放
- if (c_bank == 0) bank_busy[0] <= 0;
+ // 归一化已把 erow[c_bank] 整行读完，P·V 只读 pu_row/nzrow_r
+ if (c_bank == 0) bank_busy[0] <= 0;
```

单 bank 占用从 **206 → 142 拍**（`1 + 81 + 45 + 16`），bank 等待从 360 拍降到 0。

## 5. 为什么不需要第三 bank

- 改后 bank 等待已经是 **0**；
- A 级 81 拍/行，C 级服务 80 拍/行，瓶颈回到 A 级本身；
- 第三 bank 只能解决“等 bank”，不能解决 A 级 81 拍，所以现在加 bank 是零收益、纯面积。

---

## 6. 为什么 b2c 不加 FIFO

- A 每 81 拍才产一行，B 45 拍完成、C 80 拍服务；生产间隔受 A 限制，C 在下一次 B 完成前已取走 `b2c_v`；
- 加 FIFO 会多 1 拍（1423→1424），为 1 拍余量付 1 拍不划算；
- 改成 `translate_off` 断言监控（`f968581`）：
  1. `b2c_v` 连续高 >2 拍；
  2. `b2c_v==1 && rcp_done==1`（覆盖）；
  3. `a2b_v` 连续高 >2 拍。
- full 616 例：**0 条断言**，`lat 1423`，`mism 0`。
- 如果将来 C 级改成 81 拍触发断言，再按 `12-P2` §3.2 的两个坑补 `b_done_q` + `a2b_v` 满标志。

## 7. 可能的追问

**Q：为什么不是 1,400？**
A：A 级每行 81 拍，16 行就是 1,296 拍，加前导 82、尾部 B/C 排空 45，共 1,423；要再低只能改 A 级（QK/exp），不是 bank。

**Q：为什么 C 级不是 96？**
A：P·V 固定 4 组 × 16 拍 = 64，归一 16，共 80；跳零组只会少，不会多。

**Q：面积/功耗为什么没降？**
A：这次只改调度，不删寄存器；三角差异在 ±0.9% 内且符号不一致，属于映射噪声。要面积收益得等 P1 的 core 优化。
