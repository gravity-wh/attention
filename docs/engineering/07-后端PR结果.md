## 3. 为什么 DRC 有 38 万个

工艺数据是我们自己从 `techfile.tf` 反推出来的（PDK 里没有官方 tech LEF），三个已知缺口：

1. **金属栈不匹配**：`techfile.tf` 是 6LM_1TM 选项，而 PDK 的 `milkyway/` 下另有 9 种栈（1P6M_1TM … 1P10M_2TM），无法确认单元 LEF 对应哪一种；
2. **M1 间距被人为放宽**：`.tf` 的 M1 最小间距 0.1 µm，而单元按约 0.07 µm 建，相邻摆放即"违反"，只能放宽到 0.05 才能让 CTS 收敛；
3. **缺少官方 DRC 规则细节**（多切割 via、最小面积、off-grid 等）。

因此这 38 万个 marker 里，**相当一部分是"规则本身不对"而不是"布线质量差"**。用 Calibre + 官方 rule deck 跑一遍才能区分；在只拿到生成的 tech LEF 的前提下，本结果只能证明"流程可执行"，不能证明"版图可用"。

两个附加结论：

1. **单元库本身只用到 M1/M2/V1**（layermap 与 macro LEF 层引用统计一致：M1×11320、M2×2691、V1×2493）。6LM/9LM 之争不影响单元抽象的正确性，只决定上层布线可选几层——本流程信号层用到 M5，两个版本都覆盖。
2. **techfile 有两个版本，用哪份必须显式确认**。VM 上 `gen_techlef.sh` 默认读 `/opt/cadence/PDK/smic40/smic40ll/techfile.tf`，在 VM 上核对：`md5sum /opt/cadence/PDK/smic40/smic40ll/techfile.tf`——是 `ff619853…` 就是 6LM 版，是 `0a8d9daa…` 则是 9LM 版。

因此第 8 节第 1 条（官方 tech LEF）**确认短期无解**：只能继续用生成的 tech LEF并把"非官方"写进报告；但第 3 条（官方 rule deck）**本地已有**，见下。

## 4. 为什么后布线时序比 CTS 差这么多

| 阶段 | Setup WNS（ss） |
|---|---|
| 综合（无寄生、ideal clock） | 0 |
| CTS 后（有 clock tree，无详细寄生） | −0.52 ns |
| 后布线（qrc 提取真实 RC） | **−2.54 ns** |

三个原因叠加：

1. **布线寄生**：综合和 CTS 阶段都没有真实线 RC，qrc 提取后路径延迟大幅上升；
2. **时序驱动布线未生效**：`setNanoRouteMode -routeWithTimingDriven` 默认关，且我们为了省内存把迭代限制到 8 轮；
3. **后布线没有做 optDesign -postRoute**：流程直接提取+报时序，没有做修时序迭代。

若要改善，正确顺序是：route → `optDesign -postRoute` → 再提取 → 再报告。

## 5. 内存与运行数据（16 GB VM）

| 步骤 | 线程 | 峰值 RSS | 耗时 |
|---|---|---|---|
| init + floorplan + place | — | ~2 GB | ~3 min |
| CTS（ccopt） | — | ~3.4 GB | ~40 min |
| detail route | 4 | 13.2 GB | ~56 min |
| 提取 + 时序 | — | 1.9 GB | ~2 min |

6 线程时 RSS 冲到 14 GB 被看门狗主动终止（否则整机失联）。详见 `docs/engineering/06-内存与并发策略.md`。

## 6. 复现

```bash
# 1) 生成 tech LEF（受 PDK 授权约束，不进库）
RELAX_M1=1 bash flow/pnr/gen_techlef.sh $PWD/work_techlef

# 2) 主流程（CTS 后自动存 after_cts.enc）
make pnr VARIANT=ref TAG=ref-sm40-tt PDK=SC9MC

# 3) 布线被 OOM 中断时，从 CTS checkpoint 续跑（可指定线程数）
PNR_CPUS=4 make pnr-resume VARIANT=ref TAG=ref-sm40-tt PDK=SC9MC

# 4) 若最后两步（timeDesign/write_netlist）失败，从 pnr.enc 补跑
PNR_OUT=runs/ref-sm40-tt/pnr PNR_TOP=top_ref innovus -no_gui -files flow/pnr/finish_pnr.tcl
```
