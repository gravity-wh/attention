## 0. 任务一句话

把 `varB` 的 1,738 拍讲清楚，并只在一个可证伪的假设下改 RTL：`erow` bank 生命周期 + B→C 反压。

当前 `varB` 的 1,738 拍不是文件头写的 `max(80,41,80)=80 拍/行`。按代码里的 bank 占用：

- A 启动时占 bank（`top_varB.sv:258-268`）；
- bank 到 C 级 P·V 结束才释放（`:357-365`）；
- 单 bank 占用 ≈ A(80) + B(43) + C(80/96)；
- 2 个 bank 的吞吐下限 ≈ 101.5~109.5 拍/行；
- 16 行 ≈ 1,608~1,752 拍，实测 1,738 拍。

**先测，不要先改。**

## 2. 第一张纸：1,738 拍预算

不改 RTL，先用现有 `varB` 仿真/波形填下表：

| 项 | 符号/条件 | 实测 | 备注 |
|---|---|---:|---|
| A 级：QK 64 + exp 16 | `a_busy` | 80 | 每行 |
| B 级：倒数 + 握手 | `rcp_busy` / `b_busy` | 43~44 | 每行 |
| C 级：归一 16 + P·V | `c_busy` | 80 或 96 | 关键未知 |
| bank 等待 | `bank_busy` 满 | ? | 2 bank 的限制 |
| B→C 等待 | `b2c_v` | ? | 单寄存器 |
| 填充/排空 | 首行/末行 | ? | |
| **总计** | `done` | **1,738** | 与表一致 |

验收：各项之和与 1,738 差 ≤2 拍；若对不上，先查 C 级是否 96 拍，而不是先改 bank。

建议观测（tb 层级引用，不改 RTL）：

## 3. 第二张纸：bank + B→C 反压实验

只有第一张纸证明“bank 等待是主项”后，才做这个补丁。

### 3.1 假设

把 bank 释放从 P·V 结束提前到 normalize 结束（最后一个 `erow` 读之后），bank 占用从约 207 拍降到约 142 拍；2 bank 吞吐从约 103.5 拍/行降到约 71 拍/行，A 级 81 拍/行成为瓶颈，总周期约 **1,421 拍**。

### 3.2 必带的反压

B→C 只有单寄存器 `b2c_v`；B 完成时若 C 还没消费，会覆盖结果。必须加：

```systemverilog
// B 级完成前检查 b2c_v，保证 1-deep FIFO
if (!b_busy) begin
  if (a2b_v && !b2c_v) begin ... end
end else if (rcp_done) begin
  if (!b2c_v) begin
    b2c_v <= 1;
    ...
  end
end
```

具体写法以现有 `top_varB.sv:305-320` 为准；**不能只改 bank 释放点**。

### 3.3 验收

1. `make regress VARIANT=varB MODE=full` 六类 `mism=0`。
2. 周期在 **1,421±20 拍**；若不在，假设死掉，回滚。
3. 无 X/Z；`done` 与最后一个 `o_vld` 同拍。
4. 记录 bank 占用、b2c 等待、每行周期前后对照。

## 4. 第三张纸：装载边界

题面要求“从开始装载到结果全部输出计时”。当前 `tb_attn.sv:231-261` 先装载 768 拍再发 `start`，`lat` 不含装载。

P2 不在顶层加端口；先与 P4 约定：

- 方案 A：P4 在 tb/collect 里把 768 拍加到 `cycles`；
- 方案 B：P2 在顶层加 `S_LOAD`/`busy`，从第一个 `ld_en` 起算；这会改端口语义，必须 P3/P4 同意。

**默认走方案 A**，因为不改 RTL、不破坏三方案端口契约。

## 6. 不要做

- 不要为“80 拍/行”改 stage 长度；先证明 bank 是瓶颈。
- 不要只改 bank 释放点，不加 b2c 反压。
- 不要碰 `rtl/core` 的 exp/recip/RNE 语义。
- 不要在课堂报告前做第三 bank、exp 流水、log2e 折叠；这些是报告后实验。
- 不要把 `done` 提前到 P·V 前；流式输出必须收满 256 个。
