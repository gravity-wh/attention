## 0. 任务一句话

把 `varB` 的 1,738 拍讲清楚，并只在一个可证伪的假设下改 RTL：`erow` bank 生命周期 + B→C 反压。

当前 `varB` 的 1,738 拍不是文件头写的 `max(80,41,80)=80 拍/行`。按代码里的 bank 占用：

- A 启动时占 bank（`top_varB.sv:258-268`）；
- bank 到 C 级 P·V 结束才释放（`:357-365`）；
- 单 bank 占用 ≈ A(80) + B(43) + C(80/96)；
- 2 个 bank 的吞吐下限 ≈ 101.5~109.5 拍/行；
- 16 行 ≈ 1,608~1,752 拍，实测 1,738 拍。

**先测，不要先改。**

## 2. 第一张纸：1,738 拍预算

不改 RTL，先用现有 `varB` 仿真/波形填下表：

| 项 | 符号/条件 | 实测 | 备注 |
|---|---|---:|---|
| A 级：QK 64 + exp 16 | `a_busy` | 80 | 每行 |
| B 级：倒数 + 握手 | `rcp_busy` / `b_busy` | 43~44 | 每行 |
| C 级：归一 16 + P·V | `c_busy` | 80 或 96 | 关键未知 |
| bank 等待 | `bank_busy` 满 | ? | 2 bank 的限制 |
| B→C 等待 | `b2c_v` | ? | 单寄存器 |
| 填充/排空 | 首行/末行 | ? | |
| **总计** | `done` | **1,738** | 与表一致 |

### 2.1 第一张纸已经预填（控制级逐拍模型，不是波形）

`hw/flow/collect/cycle_model.py` 能复现三方案拍数（diff 全 0），其中 varB 的分解是：

| 项 | 拍数 | 说明 |
|---|---:|---|
| A 级每行 | 81 | 占 bank 1 拍 + QK 64 + exp 16 |
| B 级每行 | 45 | 拉 `div_start` 1 + 长除 41 + RNE 1 + 交回 1 |
| C 级每行 | **80** | 归一 16 + P·V 4 组 × 16；**不存在 96**（PV 最多 4 组，只会因跳零组变少） |
| 行间隔 | 81 / 126 交替 | 奇数行 81，偶数行多等 45 拍 bank |
| 前导 | 82 | 首行 A 启动到首行 C 开始 |
| **bank 等待合计** | **360** | 8 行 × 45 拍 —— 这就是原表里那个"?" |
| 总计 | 1,738 | 82 + 8×81 + 8×126 |

结论与 §3.1 一致：**bank 等待是主项**，可以进第二张纸。单 bank 占用按 C=80 算是
81 + 45 + 80 = **206 拍**（与 §3.1 的"约 207"吻合）；改成"归一末释放"后是 81 + 45 + 16 = **142 拍**。
两种占用 / 2 个 bank 分别给出 103 和 71 拍/行的吞吐上限，前者被 A 的 81 拍卡住时才开始排队——
这就是 81/126 交替的来历。（§3.1 的目标 1,421 拍已用模型复核：**1,423 拍**，差 2 拍。）

验收：各项之和与 1,738 差 ≤2 拍；若对不上，先查 C 级是否 96 拍，而不是先改 bank。

建议观测（tb 层级引用，不改 RTL）：

```systemverilog
$display("a=%0d b=%0d c=%0d bank=%b b2c=%b nfin=%0d",
         dut.a_busy, dut.b_busy, dut.c_busy, dut.bank_busy,
         dut.b2c_v, dut.nfin);
```

> 若 P3 不同意在 tb 加打印，就在 Verdi 里看 `bank_busy/a_busy/b_busy/c_busy/b2c_v`，把每行时间戳抄进表。

## 3. 第二张纸：bank + B→C 反压实验

只有第一张纸证明“bank 等待是主项”后，才做这个补丁。

### 3.1 假设

把 bank 释放从 P·V 结束提前到 normalize 结束（最后一个 `erow` 读之后），bank 占用从约 207 拍降到约 142 拍；2 bank 吞吐从约 103.5 拍/行降到约 71 拍/行，A 级 81 拍/行成为瓶颈，总周期约 **1,421 拍**。

### 3.2 必带的反压

B→C 只有单寄存器 `b2c_v`；B 完成时若 C 还没消费，会覆盖结果。必须加：

```systemverilog
// B 级完成前检查 b2c_v，保证 1-deep FIFO
if (!b_busy) begin
  if (a2b_v && !b2c_v) begin ... end
end else if (rcp_done) begin
  if (!b2c_v) begin
    b2c_v <= 1;
    ...
  end
end
```

具体写法以现有 `top_varB.sv:305-320` 为准；**不能只改 bank 释放点**。

> 两个必须注意的点（否则这个补丁会挂死而不是变快）：
> 1. `recip_unit` 的 `done` 是**单拍脉冲**，`r_out` 才是保持的。上面那个 `if (!b2c_v)`
>    一旦跳过，`done` 已经过去，B 会永久等下一个 `rcp_done`。必须把"算完了但没送出去"
>    锁存成 `b_done_q`，条件写成 `else if (rcp_done || b_done_q)`。
> 2. 只在 B 侧加反压不够：B 阻塞时 `a2b_v` 仍是单寄存器，A 每 81 拍产出一行仍会覆盖它。
>    A 取 bank 前要加 `&& !a2b_v`（或把 `a2b_v` 升级成带 full 标志的 1 深 FIFO）。

> 另外，实测余量只有 **1 拍**：C 占 80、行间隔 81，所以现状下 `b2c_v` 恰好不会被覆盖，
> 现有 616 例 `mism=0` 也是这么来的。反压是买这 1 拍保险——**设计里没有任何断言**，
> 将来谁把 C 级改成 81 拍，表现是静默丢一行（`nfin` 卡在 15、`done` 永不拉高），
> 而不是报错。加个 `assert (b2c_v |-> ##[1:2] !b2c_v)` 之类的检查更划算。

### 3.3 验收

1. `make regress VARIANT=varB MODE=full` 六类 `mism=0`。
2. 周期在 **1,421±20 拍**；若不在，假设死掉，回滚。
3. 无 X/Z；`done` 与最后一个 `o_vld` 同拍。
4. 记录 bank 占用、b2c 等待、每行周期前后对照。

## 4. 第三张纸：装载边界

题面要求“从开始装载到结果全部输出计时”。当前 `tb_attn.sv:231-261` 先装载 768 拍再发 `start`，`lat` 不含装载。

P2 不在顶层加端口；先与 P4 约定：

- 方案 A：P4 在 tb/collect 里把 768 拍加到 `cycles`；
- 方案 B：P2 在顶层加 `S_LOAD`/`busy`，从第一个 `ld_en` 起算；这会改端口语义，必须 P3/P4 同意。

**默认走方案 A**，因为不改 RTL、不破坏三方案端口契约。

> **决议（2026-11-14）**：暂不改口径 —— `cycles` 保持"`start`→`done`"纯计算拍数，
> 装载 768 拍不计入；这一条已写进 `05-SMIC40综合结果.md` §5 的口径声明，
> 并给出含装载的另一组数（ref 10,433 / varA 3,623 / varB 2,506，D₀/D 5.56× → 4.16×）。
> 因此 **P2 不需要动 tb，也不需要加 `S_LOAD` 端口**；任务范围收窄到第 2、3 张纸。
